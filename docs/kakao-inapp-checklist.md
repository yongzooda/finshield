# 카카오톡 인앱 브라우저 실기 — 진행 순서 (N-701)

배포 전 게이트의 마지막 항목. **폰의 실제 카카오톡**으로만 확인할 수 있다.

화면마다 실제로 뜨는 문구를 그대로 옮겨 놓았다. **적힌 것과 다른 게 보이면
그 자리가 문제 지점**이다.

## 전체 그림 — 무엇을 왜 두 번 하는가

| | 목적 | 쓰는 진술 | 되묻기 | 걸리는 시간 |
|---|---|---|---|---|
| **1회차** | 처음부터 끝까지 한 번 완주 | **1회차 진술** | **나온다** (2~4개) | 6분 |
| **2회차** | 판단 도중 앱을 나갔다 온다 | **2회차 진술** | 안 나온다 | 6분 |
| **3회차** | **이번 스프린트에 새로 만든 것들** | 진술 없음 (모델 미사용 경로 위주) | — | 8분 |

**3회차는 2026.08.28\~31에 더한 것만 본다.** 새로 만든 화면·기능이라 인앱에서
한 번도 눌러 본 적이 없다: 유보 이어가기 · 읽어주기 · 근거 각주 · 절차 안내 ·
자료 보유 표시 · 해피콜 연습. 앞의 둘과 달리 **모델을 거의 쓰지 않아** 빠르고,
크레딧도 거의 들지 않는다.

**진술은 두 개뿐이다.** 서로 다른 이유는 하나다.

- **1회차 진술** — 가입 시점(연·월)을 일부러 빼 두었다. 그래야 되묻기가 나오고,
  이번에 고친 **연·월 고르기 화면**을 볼 수 있다
- **2회차 진술** — 필요한 정보가 다 들어 있다. 되묻기 없이 곧장 판단으로 넘어간다.
  2회차는 백그라운드 시험이 목적이라 판단 화면에 빨리 도착해야 한다

# 준비 (2분) — 시작 전에 여기까지 다 해 둔다

## 준비 1. 카톡 「나와의 채팅」을 연다

## 준비 2. 세 개를 각각 따로 보낸다

한 번에 붙여 보내면 나중에 길게 눌러 복사할 때 세 개가 같이 잡힌다.
**한 줄씩, 세 번에 나눠 보낸다.**

**보낼 것 1 — 주소**

```
https://precase.vercel.app
```

**보낼 것 2 — 1회차 진술**

```
설계사를 통해 종신보험에 가입했습니다. 원금이 보장된다고 들었는데 해지하려니 낸 돈보다 훨씬 적게 돌려준다고 합니다. 가입할 때 예순여덟이었습니다.
```

**보낼 것 3 — 2회차 진술**

```
2019년 5월에 은행 창구에서 ELS에 가입했는데 원금이 보장된다고 들었습니다. 지금 원금의 40%가 손실됐습니다. 손실 가능성 설명은 듣지 못했습니다. 가입할 때 예순일곱이었습니다.
```

## 준비 3. Wi-Fi를 끈다

폰 설정에서 **Wi-Fi를 끄고 이동통신망(LTE·5G)** 으로 바꾼다.
인앱 브라우저 문제는 네트워크가 느릴 때 드러난다.

## 준비 4. 1회차 진술을 미리 복사한다 ← 꼭 지금 한다

나와의 채팅에서 **1회차 진술**(설계사를 통해 종신보험에…)을
**손가락으로 길게 누른다** → 메뉴에서 **「복사」**

> **왜 미리 복사하나** — 브라우저를 연 다음에 복사하러 카톡으로 돌아가면
> 인앱 브라우저가 닫혀서 **처음부터 다시 해야 한다.** 복사를 먼저 하고
> 링크를 누르면 그럴 일이 없다.

- [ ] 붙여넣은 글이 잘리지 않고 다 보인다

**→ 「보내기」 를 누른다.**

## 【화면 4】 되묻기 — 2~4개가 이어진다

질문이 **제목 자리**에 뜬다. 모든 질문 화면이 이 뼈대를 갖는다.

```
  (질문이 여기 제목으로 뜬다)

  몇 가지만 더 여쭤볼게요. 모르시면
  「기억나지 않습니다」를 고르셔도 괜찮습니다.

  (여기에 답변 방식이 나온다 — 질문마다 다르다)

  ┌──────────────────────────────┐
  │ 지금까지 말씀하신 내용 보기 (1가지) │           ← 회색 접이식
  └──────────────────────────────┘
```

**매 질문마다 확인**

- [ ] **한 화면에 질문이 하나만** 있다
- [ ] 맨 아래 **「지금까지 말씀하신 내용 보기 (N가지)」** 가 있다
      → **한 번 눌러 펼쳐 본다.** 내가 쓴 진술과 앞서 답한 값이 남아 있어야 한다.
      확인했으면 다시 눌러 접는다

아래는 **나올 수 있는 질문 전부**다. 순서는 그때그때 다르고, 안 나오는 것도 있다.
나오는 것만 답하면 된다.

### 질문 ─ 「언제 가입하셨나요? (연도와 월)」 ★★ 가장 중요

```
  가입한 해와 달                                 ← 굵은 라벨

  아래 칸을 누르면 연도와 달을 고를 수 있습니다.
  정확하지 않으면 「기억나지 않습니다」를 고르셔도 됩니다.
        ↑ ★ 이 안내 문장이 반드시 있어야 한다

  ┌──────────────┐
  │              │                              ← 빈 칸. iOS는 아무것도 안 보인다
  └──────────────┘

  ┌──────────┐  ┌────────────────┐
  │ 답변하기   │  │ 기억나지 않습니다  │
  └──────────┘  └────────────────┘
     (흐림)
```

**→ 순서대로**

1. **빈 칸을 누른다** → 연·월 **굴림판(휠)** 이 뜬다
   - 「2026년 8월」처럼 **이번 달이 이미 들어가 있다.** 이건 iOS 동작이라 정상이다
2. 굴림판을 돌려 **왼쪽 `2019년`, 오른쪽 `5월`** 로 맞춘다
3. 굴림판 안의 **파란 ✓** 를 누르거나, 굴림판 바깥을 눌러 닫는다
4. **파란 버튼의 글씨를 본다** ← 여기가 핵심

**확인**

- [ ] ★ 안내 문장(「아래 칸을 누르면…」)이 **입력칸 위에 있다**
- [ ] ★ 파란 버튼이 **「2019년 5월로 답변하기」** 라고 **고른 값을 보여준다**

> **그냥 「답변하기」라고만 되어 있으면 실패다. 알려주세요.**
>
> **왜 중요한가** — 칸을 누르기만 해도 iOS가 **이번 달(2026년 8월)** 을 넣는다.
> 브라우저 동작이라 페이지에서 막을 수 없다. 가입 시점은 **어느 법을 적용할지
> 정하는 기준**이라(금융소비자보호법 2021년 3월 25일 시행), 2019년 계약이
> 2026년으로 넘어가면 **다른 법으로 판단한다.** 그래서 「막는」 대신
> **버튼에 값을 적어 누르기 직전에 보이게** 했다.

**(선택) 미래 달 막기도 볼 수 있다**
굴림판을 **2030년** 으로 돌리면
**「아직 오지 않은 달입니다. 가입하신 해와 달을 골라 주세요.」** 라는 노란 경고가
뜨고 파란 버튼이 흐려져야 한다. 확인했으면 **다시 2019년 5월로 되돌린다.**

**→ 「2019년 5월로 답변하기」 를 누른다.**

  │ 기억나지 않습니다    │
  └──────────────────┘
```

**→ 아무거나 누른다.** 「기억나지 않습니다」도 정상 답변이다.

  관련 법령과 비슷한 분쟁조정 사례를 하나씩 확인합니다.

  └──────────────────────────────┘

  8초 경과 — 창을 닫지 마세요. 닫으면 처음부터 다시 하셔야 합니다.

```

- [ ] 첫 줄 「관련 법령과 비슷한 사례를 찾고 있습니다」가 **5초 안에** 뜬다
- [ ] ★ **「N초 경과」의 숫자가 멈추지 않고 올라간다**
- [ ] 단계 카드가 **세 개까지** 차례로 쌓인다
  1. `관련 법령과 비슷한 사례를 찾고 있습니다.`  (0초~)
  2. `찾은 근거로 성립 가능성을 따져보고 있습니다.`  (50초쯤)
  3. `읽기 쉬운 말로 정리하고 있습니다.`  (85초쯤)
- [ ] **90~120초** 뒤 결과 화면으로 저절로 넘어간다

> **숫자가 멈추면 그게 스트리밍이 끊긴 것이다.**
> 몇 초에서 멈췄는지 적어 두고 알려주세요.

## 【화면 7】 결과

둘 중 하나가 뜬다. **둘 다 정상이다.**

**결론이 난 경우**

```
  ┌──────────────────────────────┐
  │ 이 결과는 법률 자문이 아닙니다. … │            ← 회색 안내 상자
  └──────────────────────────────┘

  살펴본 결과입니다                              ← 제목

  결론
  ┌──────────────────────────────┐
  │       위반 가능성 높음          │            ← 진한 남색 띠
  └──────────────────────────────┘
  … 설명 …    확신도 ●●●●○

  다뤄진 쟁점
  이 내용을 바탕으로 살펴봤습니다
  근거 법령        [ 이 조문 자세히 보기 ]
  참고 조정례      [ 내 상황과 무엇이 같고 다른지 보기 ]
  준비하실 자료
  이런 경우 판단이 달라집니다
  다음에 하실 일
  사실과 다른 점이 있다면   ▸ 이 판단이 사실과 다릅니다
  판단 과정               ▸ 어떻게 이 결과가 나왔는지 보기 (13단계)
```

**유보된 경우**

```
  지금 정보로는 판단을 유보합니다                  ← 제목

  왜 유보했는지
  이 자료가 있으면 판단할 수 있습니다
  … 아래는 위와 같음 …
  다음에 하실 일
    [ 자료를 보태서 다시 상담하기 ]
```

> 유보는 **오류가 아니라 설계된 답**이다. "확신이 부족하면 결론을 내지 않는다"가
> 이 서비스의 핵심이라, 유보가 나와도 시험은 통과다.

**확인**

- [ ] 맨 위에 **「이 결과는 법률 자문이 아닙니다」** 안내 상자
- [ ] **「근거 법령」** 과 **「참고 조정례」** 카드가 보인다
- [ ] 아래로 쭉 내려 **「다음에 하실 일」** 안에 이 두 문장이 있다
  - **「분쟁조정을 신청할 권리는 이용자 본인에게 있습니다」**
  - **「금융감독원 금융민원센터 1332(평일 09:00~18:00)」**
- [ ] 맨 아래 **「판단 과정」 ▸ 어떻게 이 결과가 나왔는지 보기 (N단계)** 를
      한 번 눌러 펼친다 → 단계 목록이 나온다

# 2회차 — 판단 도중 앱 나가기 (6분)

**실기로만 확인되는 유일한 항목이다.** 시뮬레이터에서는 iOS가 네트워크를
끊지 않아 증명되지 않는다.

## 단계 1. 2회차 진술을 복사한다

인앱 브라우저를 닫고 **카톡 나와의 채팅**으로 돌아간다.
**2회차 진술**(2019년 5월에 은행 창구에서 ELS에…)을 **길게 눌러 「복사」**.

## 단계 2. 처음부터 다시 연다

같은 채팅에서 **주소를 다시 누른다** →
**「이미 문제가 생겼어요」** → **「동의하고 시작하기」** →
입력칸에 **붙여넣기** → **「보내기」**

## 단계 3. 되묻기 없이 바로 넘어간다

2회차 진술은 상품·경로·시점·나이가 다 들어 있어, 10~15초 뒤 바로
**「말씀해 주신 내용을 다 확인했습니다」** 가 뜬다.

> 되묻기가 한두 개 나와도 정상이다. 그냥 답하고 넘어간다.

**→ 「살펴보기 시작」 을 누른다.**

## 단계 4. 「N초 경과」가 20초쯤일 때 앱을 나간다

- **아이폰** — 화면 맨 아래에서 **위로 쓸어 올려** 홈으로 (홈 버튼이 있으면 홈 버튼)
- **안드로이드** — **홈 버튼**

> ⚠️ **인앱 브라우저를 `✕`로 닫으면 안 된다.** 그건 창을 닫는 것이라
> 처음부터 다시 해야 한다. **홈으로 나가는 것**이어야 한다.

## 단계 5. 다른 앱을 1분 본다

사진·날씨·설정 아무거나 연다. **1분은 채운다** — iOS가 앱을 완전히 재우기까지
30초쯤 걸려서, 30초만 나갔다 오면 시험이 안 된다.

## 단계 6. 카카오톡으로 돌아온다 ★ 여기가 결과다

카톡을 다시 열면 인앱 브라우저 화면으로 돌아온다.
**아래 세 가지 중 하나가 보인다. 전부 통과다.**

### 경우 1 — 그대로 살아 있다

```
  자료를 살펴보고 있습니다
  …
  73초 경과 — 창을 닫지 마세요. …
   ↑ 숫자가 이어서 올라가고 있다
```

**→ 아무것도 하지 않는다.** 그대로 두면 결과 화면까지 간다.

### 경우 2 — 연결이 끊겼다

```
  연결이 끊겼습니다                              ← 제목

  살펴보는 도중 다른 앱을 보시면 연결이 끊길 수 있습니다.
  말씀해 주신 내용은 아직 남아 있습니다.
  아래에서 다시 시도해 주세요.

  ┌────────────┐ ┌──────────────────┐ ┌──────────┐
  │ 다시 시도하기 │ │ 상담 다시 시작하기   │ │ 처음으로  │
  └────────────┘ └──────────────────┘ └──────────┘
        ★ 이것
```

**→ 「다시 시도하기」 를 누른다.**

### 경우 3 — 카톡이 화면을 통째로 다시 불러왔다

```
  결과는 저장하지 않습니다                        ← 제목

  이 화면을 새로 열면 판단 결과가 남지 않습니다.
  프리케이스가 결과를 저장하지 않기 때문입니다.
  말씀해 주신 내용은 아직 남아 있어 지금 다시 살펴볼 수 있습니다.
  2분 정도 걸립니다.

  ┌────────────┐ ┌──────────────────┐ ┌──────────┐
  │ 다시 살펴보기 │ │ 상담 다시 시작하기   │ │ 처음으로  │
  └────────────┘ └──────────────────┘ └──────────┘
        ★ 이것
```

**→ 「다시 살펴보기」 를 누른다.**

### 경우 2·3의 확인

- [ ] 버튼을 눌렀을 때 **진술을 다시 쓰라고 하지 않는다**
      (바로 「자료를 살펴보고 있습니다」로 넘어가야 한다)
- [ ] 판단이 다시 돌아 **결과 화면까지 간다**

## 단계 7. 한 번 더 — 3분 (여유 있으면)

같은 방식으로 이번엔 **3분** 나갔다 온다. 결과는 위 세 경우 중 하나여야 한다.

> **30분을 넘기면** 「상담 내용이 사라졌습니다」가 뜬다. **그건 정상이다** —
> 개인정보를 저장하지 않아 30분 뒤 세션이 만료되도록 만들어 두었다.

**2회차 끝.**

# 3회차 — 이번에 새로 만든 것 (8분)

**모델을 거의 쓰지 않는다.** 판단을 한 번만 돌리고 나머지는 정적 화면이라,
앞의 두 회차보다 빠르고 크레딧도 거의 안 든다.

## 【3-1】 해피콜 연습 — 모델을 전혀 안 쓴다

주소창에 **`precase.vercel.app/happycall`** 을 친다.
(또는 랜딩 → 「가입 전에 확인하기」 → 보험 상품 고르고 결과까지 간 뒤,
「가입하면 확인 전화(해피콜)가 옵니다」 절의 버튼)

| 할 일 | 봐야 하는 것 |
|---|---|
| 경로 두 개가 보인다 | 「전화(TM)로…」 · 「은행 창구에서…」 |
| **「은행 창구에서 보험에 가입한 경우」** 를 고른다 | 안내에 **「녹음됩니다」** 가 있다 |
| 「연습 시작하기」 | 질문이 **한 화면에 하나만** 나온다 |
| 첫 질문에서 **「아니요, 지금 처음 듣습니다」** | 답을 고르면 **해설이 열린다.** 고르기 전에는 「다음 질문」 버튼이 없다 |
| 「다음 질문」 | **「예금입니까, 보험입니까?」** 라는 확인 단계가 나온다 ← 분기가 갈린 것 |
| 끝까지 답하고 「마무리 보기」 | 내가 고른 답이 그대로 나열된다 |
| 「다른 답으로 다시 해보기」 → 첫 질문에서 이번엔 **「네, 보험이라고 안내받았습니다」** | 확인 단계를 **건너뛰고** 곧장 다음 질문으로 간다 |

## 【3-2】 가입 전 확인 — 읽어주기·보유 표시

랜딩 → **「가입 전에 확인하기」** → 아무 상품이나 골라 결과까지.

| 할 일 | 봐야 하는 것 |
|---|---|
| 결과 첫 화면 | **「n단계 중 1단계」** 와 진행 바가 있고, 한 화면에 **한 절만** 있다 |
| **「다음: ○○ →」** 를 눌러 끝까지 | 절이 하나씩 바뀐다 ★ **인앱에서 뒤로가기가 이전 절로 가는지** |
| 아무 절에서 **「전부 한 화면에서 보기 (인쇄용)」** | 나뉜 절이 전부 한 장에 나온다 |
| 「판매자에게 확인할 것」 절 아래 | **「질문 읽어주기」** 버튼이 있다 |
| 눌러 본다 ★ **소리 확인** | 한국어로 읽는다. 누르면 **「읽기 멈추기」** 로 바뀐다 |
| 「이런 말이 나오면 멈추세요」 절 | **「멈춤 신호 읽어주기」** 도 같은 식으로 동작한다 |
| **「지금 확인해 두실 것」** 의 자료 항목 | 각 항목에 **네모 칸(체크)** 이 있다 |
| 칸을 두어 개 눌러 본다 | 「보유」 표시가 붙고, 아래 **「아직 없는 자료가 n개」** 의 숫자가 줄어든다 |
| 전부 누른다 | **「필요한 자료를 전부 가지고 계신 것으로 표시하셨습니다」** 로 바뀐다 |

## 【3-3】 판단 결과 — 각주·절차 안내·읽어주기

**「데모 사례」 → 「판단 결과」** 를 연다 (판단을 새로 돌리지 않아도 된다).

| 할 일 | 봐야 하는 것 |
|---|---|
| 결론 문단을 읽는다 | 문단이 **2\~3문장씩 나뉘어** 있다. 한 덩어리가 아니다 |
| 문장 속 **파란 밑줄 조문번호**(「제47조」 등)를 누른다 ★ | 아래 **근거 법령 카드로 이동**한다. 손가락으로 눌러도 잘 눌린다(8/30에 넓혔다) |
| 「결론 읽어주기」 ★ **소리 확인** | 제목과 결론을 읽는다 |
| 아래로 내려 **「분쟁조정은 이렇게 진행됩니다」** | 1\~5단계가 보이고, 그 아래 **「절차의 근거 조문」** 카드(금소법 36·39조) |
| 더 내려 **「자료를 구하는 방법」** | 금소법 **제28조** 카드가 함께 있다 |
| **「가입 시점」** 을 본다 | **2008-06** 이다 (예전엔 2010-01이 나왔다 — 8/31에 고쳤다) |

## 【3-4】 유보 이어가기 ★ 이번 회차의 핵심

**「데모 사례」 → 「판단 유보」** 는 세션이 없어 이어가기가 안 된다.
**실제로 상담을 한 번 돌려야 한다** — 이 회차에서 모델을 쓰는 유일한 곳이다.

1. 랜딩 → **「이미 문제가 생겼어요」** → 동의 → **2회차 진술**을 붙여넣고 보낸다
2. 판단이 끝나기를 기다린다 (2분)
3. **유보가 나오면** 아래 「자료를 보태서 다시 상담하기」 를 누른다
   (결론이 나오면 이 항목은 건너뛴다 — 유보가 나올 때까지 반복하지 않는다)

| 봐야 하는 것 |
|---|
| 제목이 **「이어서 진행합니다」** 다 (「어떤 일이 있었는지…」가 아니다) |
| **동의 화면이 다시 나오지 않는다** |
| 지난번에 안내한 **필요 자료 목록**이 카드로 보인다 |
| 입력창 라벨이 **「보탠 내용」** 이다 |
| 아무 말이나 한 줄 적고 보내면 상담이 **이어진다** (처음부터가 아니다) |
| 여기서 **새로고침**하면 → 동의 화면부터 시작한다 (정상이다) |

# 곁다리 — 한 번씩만 (2분, 선택)

아무 화면에서나 **맨 아래까지 내리면** 회색 영역에 링크 세 개가 있다.
**「검증 결과」 · 「데모 사례」 · 「개인정보 처리방침」**

랜딩에는 그 아래 줄에 **「분쟁 패턴 지표」 · 「MCP 서버」** 가 더 있다 (심사·개발자용이라
랜딩에만 둔다 — G-2). 다른 화면에서 이 둘이 보이면 그건 잘못된 것이다.

| 할 일 | 봐야 하는 것 |
|---|---|
| **「검증 결과」** | 「결론을 냈을 때의 정확도 **92.3% (60/65)**」와 그 아래 **「95% 신뢰구간 83.2~96.7%」** 가 **함께** 보인다(2026.08.31 재적재분). **「안전성 시험」 섹션**과 **「아직 검증하지 못한 것」**에 기각한 실험이 보인다. 표가 좌우로 밀리지 않는다 |
| **「데모 사례」** | 3종이 보이고 전부 열린다. 열면 맨 위에 노란 띠로 **「데모 사례입니다 — 실제로 상담하신 결과가 아닙니다」** 가 붙어 있다 |
| 랜딩의 **「가입 전에 확인하기」** | 질문 3개(상품 → 경로 → 나이)를 고르면 결과까지. 모델을 안 쓰는 경로라 빠르다 |
| 폰 설정에서 **글씨 크기를 키운 뒤** 아무 화면 | 글자가 겹치거나 잘리지 않는다 |

# 참고 — 폰에서 다시 볼 필요가 없는 것

미리 재 두었다.

- **프로덕션 스트리밍** — 카톡 iOS UA로 전 구간 1회. 첫 이벤트 1.6초, 10초 하트비트가 오차 0.1초로 도착, 90.3초 완주
- **압축 버퍼링** — Vercel 엣지가 `content-encoding: br`을 붙이지만 청크별로 flush돼 버퍼링 없음
- **안드로이드 Chrome** — 에뮬레이터(API 36)에서 판단 스트림 88.9초 완주, 하트비트 오차 0.2초
- **375px 레이아웃** — 랜딩·가입 전 확인·검증 결과·판단 결과·근거 상세에서 가로 스크롤 0, 48px 미만 터치 영역 0
- **iOS 입력창 자동 확대** — 진술창 글꼴 18.9px라 확대 조건(16px 미만)에 걸리지 않는다
- **글꼴** — 외부 폰트를 받지 않는 시스템 스택이라 인앱에서 즉시 렌더된다
- **끊김 복구 경로** — 429·503·연결 끊김에서 세션을 보존하고 재시도 버튼을 띄우는 것까지 재현 확인
- **WKWebView 전 구간** — 상담 진입부터 결과·근거 상세·뒤로가기까지 시뮬레이터에서 눌러 가며 완주. PII 마스킹 통과 · 키보드가 「보내기」를 가리지 않음 · 핀치 확대 동작
- **백그라운드 서스펜드(근사)** — 앱과 WebContent를 90초간 `SIGSTOP`으로 얼렸다 풀었을 때 스트림이 살아남아 결과가 떴다

남은 불확실은 **실기의 백그라운드 정지**뿐이다. `SIGSTOP`은 JS와 타이머를 멈추지만,
실기에서는 iOS가 **네트워크 연결까지 끊는다.** 그 차이가 2회차 단계 6에서 갈린다.
