# B-EMBED-01 재정의 영향 분석과 순서

## 1. 결정과 근거

`B-EMBED-01`을 `AI-007` 파이프라인에 맞춰 재정의한다. Vector 단계는 1차 후보 생성으로 두고, Metadata Filter→Keyword→Vector→Authority/Freshness/Relevance Rerank 전체를 별도 component blocker로 평가한다.

근거는 두 가지 실측이다.

- Gate run `33870910880`에서 정답을 밀어낸 문서는 corpus 잡음이 아니라 대상 식별자와 시점만 다른 지정 hard negative였다. 다중 항목 침입 56칸 중 53칸이며 다른 가족 문서 침입은 500칸 중 3칸이다.
- 개발용 run `33877345188`에서 모든 정답이 168개 unit 중 상위 8위 안에 있었고 Recall@10은 1.00이다. 표현의 한계가 아니라 top-k 폭의 문제다.

`AI-006`은 기관·상품 식별에서 Vector 유사도만으로 사실을 확정하지 말라고 규정하고, `AI-007`은 그 판별을 Metadata Filter와 Rerank 단계에 배정한다. 현재 `B-EMBED-01` 수용식은 그 책임을 Filter도 Keyword도 Rerank도 없는 Vector 단계 단독에 요구한다. `AGENTS.md`의 `ADR은 상위 요구·DB·기능명세를 덮지 않는다`에 비추어 하위 blocker의 합격식을 상위 요구사항 구조에 맞춘다.

이 재정의는 측정 결과를 본 뒤 수용식을 바꾸는 것이다. 그 사실을 숨기지 않는다. v2 실측값과 개발용 측정값은 삭제하지 않고 계속 공개 보존하며, 제출 문서에 변경 사유와 시점을 명시한다.

## 2. Evidence 무효화 영향

ADR 본문 변경은 현재 유일한 PASS인 `B-MODEL-01`을 무효화한다.

`adrDecisionDigest`는 Gate 상태값, 14.2·14.4 blocker 표의 상태 열, 14.1의 `EVID-*` 행만 정규화하고 나머지 본문을 그대로 해시한다. 채택된 결과의 `adr_decision_sha256`이 현재 ADR digest와 다르면 검증기가 실패한다.

편집 유형별 실측 결과는 다음과 같다.

| 편집 유형 | ADR decision digest | 기존 PASS |
|---|---|---|
| Gate 상태만 변경 | 동일 | 유지 |
| blocker 상태값만 변경 | 동일 | 유지 |
| blocker 설명·해제 조건 문구 변경 | 변경 | 무효 |
| 15.1 합격선 표 변경 | 변경 | 무효 |
| 새 blocker 행 추가 | 변경 | 무효 |

재정의에 필요한 편집은 5.2, 14.2, 15.1, 15.2에 걸쳐 있고 모두 아래 세 유형이다. 따라서 무효화를 피할 수 없다.

검증기는 ADR 표에 `PASS` 행이 하나도 없으면 evidence 검증을 건너뛴다. 그러므로 ADR 변경 PR에서 `B-MODEL-01` 상태를 `NOT-EVALUATED`로 되돌리고 `evidence/provider-stack-gate.json`의 entry를 제거하면 CI는 통과한다. 결과 파일 `evidence/results/B-MODEL-01/33783765337.json`과 실행 이력은 삭제하지 않고 보존한다.

`B-MODEL-01` 재시험 비용은 Anthropic 실제 요청 100회이며 기존 harness와 합격식을 그대로 사용한다. 재실행 전에 scope 파일이 바뀌지 않았는지 확인한다.

## 3. 순서

PASS가 하나도 없는 창을 최소화하도록 ADR을 건드리지 않는 준비를 먼저 끝낸다.

### 1단계 — ADR 미변경 준비

1. 이 영향 분석과 순서 문서.
2. 재정의된 두 blocker의 수용식·평가셋 사전등록 문서. 측정 전에 검토·병합한다.
3. 새 시나리오 가족의 미측정 평가셋과 두 harness, 오프라인 계약 시험. pin된 파일을 수정하지 않고 새 파일로 만든다.

### 2단계 — ADR 변경 한 번 (완료)

4. 한 PR에서 5.2·14.2·15.1·15.2 재정의, `B-RETRIEVAL-01` 행 추가, `B-MODEL-01` 상태 되돌림과 index entry 제거, 검증기 blocker 목록 갱신, `HANDOFF.md`·README·운영 문서 동기화를 수행했다. 새 blocker의 trusted policy는 harness가 생기는 PR에서 등록한다. `PASS`가 0개이므로 그전까지 검증기는 evidence 검사를 건너뛴다.

의존성은 추측으로 미리 넣지 않았다. `pdfjs-dist` 같은 항목을 나중에 추가하면 `B-MODEL-01`이 다시 무효가 되어 재측정이 한 번 더 필요하다. 쓰지 않는 의존성을 미리 넣는 위험과 재측정 비용을 견줘 후자를 선택했다.

### 3단계 — 재측정과 채택

5. `B-MODEL-01` 재실행과 별도 채택 PR.
6. 재정의된 `B-EMBED-01` 새 평가셋 실행과 채택.
7. component blocker 실행과 채택.

## 4. 수용식 초안

확정이 아니라 2단계 사전등록 PR에서 검토할 초안이다. 숫자는 측정값이 아니라 파이프라인 요구에서 유도한다.

- 1차 후보 생성 단계: 후보 풀 `k`에서 관련 unit Recall `= 1.00`. 1단계에서 빠진 근거는 이후 어떤 단계로도 복구할 수 없으므로 부분 회수를 허용하지 않는다. `k`는 Rerank 비용·지연 예산에서 정하고 관측된 순위 분포에 맞춰 정하지 않는다.
- 종단 component 단계: 현재 사전등록값인 Recall@5 `≥0.90`, 위험 핵심 Recall@5 `= 1.00`, Precision@5 `≥0.80`, Provider P95 `≤1,500ms`를 그대로 적용한다. 완화하지 않는다.

두 단계 모두 새 시나리오 가족의 미측정 평가셋이 필요하다. 노출된 v2를 재사용하지 않는다.

## 5. 지킬 것

- 이 문서는 계획이며 Gate 상태를 바꾸지 않는다. `B-EMBED-01`은 `NOT-EVALUATED`, Implementation Gate는 `NO-GO`다.
- v2 실측값과 개발용 측정값을 삭제하거나 재채점해 PASS로 바꾸지 않는다.
- 종단 합격선을 완화하지 않는다. 불리한 질문을 빼지 않는다.
- 후보 생성 결과를 종단 품질 합격으로 표시하지 않는다.
- `B-MODEL-01` 되돌림은 결과 파일과 실행 이력을 보존한 상태로만 수행한다.
- 재정의를 이유로 과거 Git 이력을 재작성하지 않는다.
