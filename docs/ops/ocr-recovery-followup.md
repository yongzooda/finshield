# OCR·복구 후속 검증 사전등록 (2026-09-09)

사용자는 가입 후 결과 개선과 함께 사진·스캔 PDF 품질, 중단·재접속·동시 이용 복구의 남은 문제 해결을 요청했다. 과거 실패와 현재 Gate를 유지한다. GitHub 결제 장애로 main 실행·Adoption이 차단돼 있어 아래 로컬/보호 배포 개발 검증을 정식 Gate 채택으로 표시하지 않는다.

먼저 기존 `ocr-url-failure-diagnostic.md`의 고정 PDF SHA·Provider 옵션·출력 제한을 그대로 사용해 한 번 개발 진단한다. main 전용 Workflow 환경을 위조하지 않고 내보낸 진단 함수로 호출하며 실제 로컬 HEAD와 harness digest를 기록한다. 정확한 인식 문자열을 본 뒤 변경안을 정하고 새 가족·입력·합격식을 고정하기 전 재평가하지 않는다. 같은 평가셋의 반복 결과를 새 품질 PASS로 쓰지 않는다.

복구는 별도 진행 브랜치의 미병합 0053 쓰기 차단을 현재 코드·원격 DB와 대조한다. 이전의 정상·실패 종결 검증을 반복 구현하지 않는다. 실제 Provider 결과 미확정 예약은 보존하며 중복 작업·오래된 Lease·취소 경합·초기 연결 단절을 서로 구분한다. 변경 전 장애 목록과 기대 terminal·중복 비용/Passport/알림 0 기준을 고정하고 모든 실패를 보존한다.

후속 원격 확인: 이슈 #277과 main 진단 run 34198597628(성공, SHA 0a95b545)을 확인하니 진단은 이미 끝나 있었다. 오류 7쪽의 `example`→`exaimple`, 최소 confidence 0.591이며 정상 3쪽은 0.989였다. 추가 Provider 진단을 하지 않는다. 로컬 시도는 설정 검사에서 중단돼 실제 전송 0건이다. PR #281의 저신뢰 확인 구현과 #285의 Lease fencing을 현재 코드에 대조해 재사용한다. 이전 완료 작업을 다시 구현하지 않는다.
