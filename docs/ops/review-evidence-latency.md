# 상품 조건 설명·검증 지연·가입 후 공식 근거

2026-09-09. 사용자 승인 범위는 심사 체험의 세 결함 수정이다. AI-009·AI-010·AI-012·AI-016·RES-008·PC-005를 따른다. 전체 Gate는 변경하지 않는다.

## 수정 전과 검증 기준

기준 배포 e9d6e9d의 PDF 6항목은 검증·저장 92.981초와 전처리 13.596초, 정상 Text 4항목은 검증·저장 67.668초였다. 금리·한도는 UNKNOWN이며, 가입 후 Agent의 마지막 실제 표본은 공식 조회 0건·Sales 인용 실패로 PARTIAL이다.

실측 전에 다음 확인 범위를 등록한다. 같은 PDF와 정상 예방 Text 각각 첫 실행을 보존하고, 시간 개선 목표는 검증·저장 60초 이내로 둔다. 실패 표본을 버리지 않으며 목표 미달은 그대로 보고한다. 반복 측정 P95나 정식 Gate 평가로 표시하지 않는다.

- 상품 금리·한도에서 실제 공식 페이지의 종료 전 조건과 보증 종료일을 출처와 함께 설명한다. 현재 가입·과거 계약·개인 승인을 혼동하지 않는다. CoVe 미확인을 임의로 확정하지 않는다.
- 모든 고정 Agent와 독립 조회·Judge가 실행되고 새 인용 오류·부분 기술 실패가 없어야 한다. 정상 예방 문구에는 위험 행동 라벨이 없어야 한다.
- 같은 Case의 가입 후 점검은 계약 차이와 네 답변, 실제 두 Agent 및 공식 본문 조회를 저장한다. 다른 세션 조회·중복 요청·기준 Passport 불변을 확인하고 문구 차이만으로 위법을 확정하지 않는다.
- 실행 후 새 시험 계정·원본·Case 삭제와 비용 정산을 확인한다. 과거 기록과 기존 운영 예산은 보존한다.

## 구현 경계

고정 Domain Agent의 반복 읽기 경로는 사전 정의하고 CoVe·Red Team의 별도 모델 검색 선택은 유지한다. Agent 병렬화·모델 교체·예산 증액은 하지 않는다. 독립 검토의 근거도 Judge에 전달하되 기존 사후 정책을 적용한다. 종료 전 수치는 명시된 공식 필드에서만 추출하고 맥락 근거로 저장한다.

가입 후 문서 확인 Tool은 기존 법제처 Adapter로 설명의무 원문을 읽는다. 요청한 조문이 없을 때 다른 조문으로 대체하는 오류를 차단한다. 기존 공식 출처·허용 도구 경계를 유지하며 새 정의와 Manifest는 과거 버전을 보존해 등록한다.

## 첫 실측과 후속 수정

첫 후보의 같은 PDF는 7개 항목으로 추출됐고 검증·저장 76.392초, 인용 오류 없이 저장됐다. 금리·한도의 종료 전 수치와 종료일은 보존됐지만 60초 목표에 미달했다. 원본은 `evidence/development/review-evidence-latency/pdf-first-live.json`이다.

가입 후 공식 본문 조회 세 건은 성공했으나 Sales의 출력 항목 범위 검사에서 실패해 PARTIAL이었다. 각 판단 묶음에 다른 묶음의 계약 비교 참조가 함께 전달되는 입력을 확인해 현재 묶음의 비교만 전달하도록 수정한다. 개인 승인 자료 부족은 유지한다. 단순 계약 차이 답변을 즉시 사칭 신고로 연결하는 규칙도 서면 확인·정정 문의로 바로잡는다. 이 첫 실패를 지우지 않는다.

고정 Domain의 담당 Claim만 판단 입력에 넣어 중복 출력을 줄인다. Agent 수·순서, CoVe·Red Team 전체 중요 항목은 유지한다. 후속 후보도 같은 PDF와 정상 Text의 첫 실행을 보존하며 목표를 낮추지 않는다.

두 번째 후보 v14의 PDF는 6항목·76.318초였으나 CoVe 응답 1건이 1,000 token에서 잘려 실패했고, 한쪽 관계밖에 없는 모델 CONFLICT를 최종화에 전달해 DB의 양쪽 근거 제약(23514)이 전체 저장을 거부했다. 정상 Text 4항목은 62.544초·전체 성공이지만 시간 목표 미달이다. 첫 실패와 후속 실패·성공을 모두 `evidence/development/review-evidence-latency/`에 보존한다.

동일 Case의 가입 후 후속 점검은 COMPLETED, Sales·Regulation 성공, 실제 공식 조회 3건이고 계약 금리 3%→8.2% 차이에 CORRECTION_OR_INQUIRY를 저장했다. 동일 요청 키는 같은 Job을 반환했고 새 로그인 후 조회와 기존 Passport 불변을 확인했다.

후속은 같은 Agent 내부 판단 묶음을 3→2항목으로 줄여 긴 출력·토큰 잘림과 대기를 완화한다.
