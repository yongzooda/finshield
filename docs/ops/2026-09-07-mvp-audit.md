# 2026-09-07 서비스 완성도 점검

**결론: 원래 기획한 P0 MVP는 아직 완료되지 않았다.** 화면과 일부 서버 경로는 구현돼 있지만, 회원 기록 조회와 공개 체험에서 실제 장애가 재현됐다. 파일 입력, 독립 검증, 적합성, 가입 후 Agent 재사용, 내구성 있는 재검증에도 구현 공백이 있다. 단위 테스트 통과나 Provider 구성요소의 채택 이력을 전체 서비스 완료로 해석하면 안 된다.

## 점검 기준과 방법

- 기준 코드: `origin/main`의 `82e5dd8`. 점검일: 2026-09-07.
- 정본: [통합 요구사항](../02-integrated-requirements.md), [제품 기획](../01-product-plan.md), [DB 명세](../03-database-spec.md), [Provider ADR](../adr/001-p0-provider-stack.md).
- 완료 기준: 햇살론15 관련 대출 권유 한 시나리오를 Text·Image·PDF로 입력하고, Claim 확인·검증·Passport·재검증·같은 Case의 가입 후 보호까지 실제로 완료한다.
- 방법: 요구사항과 코드 대조, 기존 자동 테스트, 실제 배포본의 공개 체험 및 사용자 제공 시험 계정의 읽기 경로 확인, 수정 UI의 합성 응답 기반 브라우저 검증.
- 시험 계정의 비밀번호·토큰·개인 프로필은 이 문서와 시험 산출물에 저장하지 않았다. 기존 기록의 삭제·수정과 실제 금융 거래는 실행하지 않았다. 이번에 만든 합성 Text 시험 Case만 중단·삭제 요청했다.
- 로컬 화면 시험은 외부 Provider·DB를 합성 응답으로 대체했다. 화면 시험 통과는 실서비스 연동이나 판단 품질의 통과가 아니다.

| 알림 조회 | 정상 응답 | API 200, 알림 0건. 재검증 완료 알림의 생성·중복 방지는 별도 검증이 필요하다. |

## 우선 고칠 코드

1. **서버가 검증할 Claim을 직접 복원해야 한다.** [verify route](../../src/app/api/finshield/verify/route.ts)는 `claim_id`·`claim_ref`의 문자열 여부만 확인한 뒤 브라우저가 보낸 `statement_masked`·`materiality`를 모델에 전달한다. DB에 저장된 확정 Revision을 소유권과 함께 읽고 입력 Schema·PII Gate를 강제해야 한다. 실제 개인정보를 보내는 공격 시험은 하지 않았다.
2. **CoVe·Red Team의 실제 출력 계약을 맞춰야 한다.** [model-adapter](../../src/lib/finshield/agents/model-adapter.ts)의 `decide`는 Domain 출력만 생성한다. [runner](../../src/lib/finshield/agents/runner.ts)의 `runReviewAgent`는 다른 Schema를 검사한다. 정상 검토 응답을 주입하는 단위 테스트로는 이 오류가 드러나지 않는다.
3. **근거가 실제 조건을 담아야 한다.** [Tool 등록부](../../src/lib/finshield/tools/index.ts)의 Snapshot·경보·위험패턴·약관·분쟁 5개 구현은 `notLoadedYet`다. [상품 검색](../../src/lib/finshield/tools/registry.ts)은 제목 `ILIKE` 검색 후 제목을 발췌로 사용한다. 상품 본문·정확한 수치·적용 조건과 Hybrid 검색을 연결해야 한다.
4. **판정과 저장 계약을 함께 검증해야 한다.** [finalize](../../src/lib/finshield/finalize.ts)는 근거의 관계를 Claim+Evidence가 아닌 Evidence ref 하나로 저장한다. 검토 실패 시 Red Team을 `NONE_FOUND`로 간주한다. [DB 계약](../../supabase/migrations/0010_agent_tool_evidence.sql)의 Red Team 상태와 [추가 Migration](../../supabase/migrations/0024_cove_red_team_agents.sql), 최종화 RPC 전체를 묶어 테스트해야 한다. 적합성과 거래 위험 축은 별도 규칙·근거에 따라 계산해야 한다.
5. **재검증을 요청 수명과 분리해야 한다.** [revalidate](../../src/lib/finshield/revalidate.ts)는 큐에서 자기 Job이 아닌 앞선 Job의 Lease를 취득한 뒤 오류를 반환할 수 있다. Heartbeat 실패도 무시한다. 알림 Dispatcher는 다른 종류의 Outbox 이벤트를 `UNSUPPORTED_EVENT`로 끝내므로 다른 처리기의 작업을 없애지 않는지 확인해야 한다.
6. **기존 회원 기록 상세의 502 원인을 확인해야 한다.** [상세 route](../../src/app/api/finshield/cases/[id]/route.ts)의 11개 조회 중 하나만 실패해도 전체가 실패한다. 운영 Migration·각 테이블 권한·PostgREST 계약을 분리 진단하되 일부 근거 누락을 정상 결과로 숨겨서는 안 된다.

## 이번 화면 수정

- 홈의 우선 동작을 대출 권유 확인으로 정하고, 검증 기록·가입 후 보호를 바로 찾을 수 있도록 배치했다.
- PC 상단 메뉴와 모바일 하단 메뉴를 동일한 네 항목으로 맞췄다. 로그인·입력·상태·카드·버튼·글자 크기를 공통화했다.
- 기존 `/precase`의 별도 서비스 소개를 없애고 FinShield 계정과 Case 목록에서 가입 후 보호로 이어지게 했다.
- 개발자용 설명과 중복 안내를 줄이고, 출처의 해시·상세 정보와 진행 이력은 펼쳐서 볼 수 있게 했다.
- Passport의 이전 버전 선택을 추가하고 DB의 실제 완료·종합 결과 코드에 맞는 한국어 표시를 보완했다.
- intake·검증·공개 체험·재검증의 스트림이 종결 이벤트 없이 끝나면 오류를 표시한다. 마지막 개행이 없어도 완료 이벤트를 처리한다. 이는 서버의 내구성·시간 상한 문제를 해결한 것이 아니다.
- 프로필·알림·기록 조회와 주요 저장 동작에 네트워크 오류 안내를 보완했다. 데이터 조회 실패 시 빈 프로필을 저장하도록 유도하지 않는다.
- 재검증의 비교 결과가 없을 때 ‘변화 없음’으로 표시하지 않으며, 가입 후 일반 관리 결과도 ‘조치 없음’ 대신 계약 자료 보관 행동으로 표시한다.
- 신뢰센터의 과거 통과 이력을 현재 완료처럼 보이게 하던 문구를 수정했다. 시험용 합성 자료 제한은 유지한다.

## 다음 완료 순서

실행 중단·기록 상세·입력 신뢰 경계·검토 Schema를 먼저 해결한다. 이후 누락된 공식 자료와 판정·저장 계약, 파일 처리, 내구성 재검증, 가입 후 Agent 연결을 완성한다. 구현된 실제 경로로 Text·Image·PDF 동일 시나리오를 실행하고, 실패·취소·삭제·다른 기기 복원을 포함한 Release Gate를 통과시킨다.

이전 공모전 제출 문서는 ‘계획한 MVP가 모두 완료됐다’는 가정으로 작성됐다. 현재 코드의 완료 증거로 사용할 수 없으며, 실제 완료 범위와 시험 결과를 반영해야 한다.
