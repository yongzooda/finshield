## 1. MVP 구현 범위

### 1.1 구현한 범위 — 실제로 동작하는 것만

**세 축을 모두 구현해 배포했다.** ③ 개선 축은 같은 코퍼스·같은 집계 함수를 관점만 바꿔 쓰므로 새 엔진이 필요하지 않았고, 도구 5종은 **MCP로 외부에 공개**했다.

| 구분 | 구현 내용 |
|---|---|
| **에이전트** | **4계층 파이프라인 전 구간** — ① 상담(되묻기·사실관계 정제) → ② 조사(도구 오케스트레이션) → ③ 판단(원문 미접근·확신도 산출) → ④ 안내(표현 변환). 확신도 임계 검사와 유보 분기, **유보 후 상담 이어가기** 포함 |
| **도구** | **MCP 도구 5종 전부** — `lookup_statute` · `search_precedent` · `search_case` · `check_documents` · `analyze_risk_pattern`. 전부 읽기 전용 |
| **화면** | **소비자 9개 전부** — 랜딩 · 사전 점검 · 상담 대화 · 판단 진행 · 판단 결과 · 근거 상세 · 검증 결과 · **해피콜 응답 연습** · 개인정보 처리방침. 자료 체크리스트와 실행 로그는 판단 결과 화면 내 섹션으로 흡수<br/>**기관 4개** — 채널별 쟁점 집중도 · 반복되는 쟁점 · 소비자 특성별 분포 · 판매 과정 점검 항목<br/>**개발자 1개** — MCP 서버 연결 안내 |
| **데이터** | 조정례 **388건** 구조화 적재(검색 코퍼스 268 : 검증셋 120) · 약관 조항 266건 · 용어 정의 77쌍 · 판단 논거 332건 · 쟁점 태그 34종 · 삭제 조문 스냅샷 6건 · 검증 통계 |
| **외부 연동** | 법제처 국가법령정보 OPEN API (법령·판례) — 캐시 및 스냅샷 폴백 포함 |
| **공개 인터페이스** | **MCP 서버** (`POST /api/mcp`) — 도구 5종을 외부에서 호출할 수 있다. 읽기 전용, 인증 없음, 요청 본문 미저장. 도구 설명문에 **알려진 결함을 함께 적는다**(법제처 판례 검색의 부분일치 등) |
| **데모** | **사전 생성 데모 3종** — 예방 / 판단-결론 / 판단-유보. **배포 번들의 정적 자산**이라 DB·모델·외부 API 상태와 무관하게 열람 가능 |
| **안전 장치** | PII 자동 마스킹 + 잔존 시 전송 차단 · 환각 방지 렌더 제약 + CI 자동 대조 · 저장 금지(봉인 세션) · 도구 호출 상한 · IP 레이트 리밋 · 예산 하드 쿼터 · 헬스체크·알림 |

### 1.2 구현 범위에서 제외한 것 *(참고 — 본 명세서의 대상이 아니다)*

- **파일 업로드 UI** — 약관은 대화창 텍스트 붙여넣기로 받는다. **없어서 못 하는 것이 아니라 두지 않기로 한 것이다** — 파일을 받으면 어딘가에 보관해야 하고, 그러면 「아무것도 보관하지 않는다」가 무너진다. 화면에서 그 이유를 밝히고 붙여넣기 경로를 안내한다
- **로그인·회원가입·상담 이력 저장** — 같은 이유다. 대신 **결과를 이용자 기기에 PDF·종이로 남기는 경로**를 뒀다
- **금융투자·은행 권역 확대** · **금융회사 판매 프로세스 연계**

|---|---|---|---|
| 사전 점검 입력 | 상품군(업권 2단 선택) → 판매채널(6지선다) → 연령. **한 화면에 하나씩**, 자유 텍스트 없음 | 사전 점검 `/precheck` | 완료 |
| 분쟁 빈발 쟁점 제시 | 해당 조합에서 실제 분쟁이 된 쟁점을 **건수와 함께** 제시 | 사전 점검 결과 | 완료 |
| 확인·보관 항목 안내 | 채널별로 지금 확인·보관해야 할 자료 안내 | 사전 점검 결과 | 완료 |
| 집계 범위 정직 표시 | 조합에 딱 맞는 사례가 부족하면 **기준을 넓혀 집계**하고, **넓힌 사실과 실제 집계 축을 화면에 표시** | 사전 점검 결과 | 완료 |
| **가입 전 브리핑** | 「판매자에게 확인할 것」·「이런 말이 나오면 멈추세요」 두 절. 문장은 **코드 상수**이고, 무엇이 뜰지는 도구가 반환한 쟁점과 확정 슬롯이 정한다 — **도구가 주지 않은 쟁점의 문장은 나올 수 없다.** 멈춤 신호는 조건이 안 맞으면 절 자체가 사라진다 | 사전 점검 결과 | 완료 |
| **브리핑 읽어주기** | 두 절을 브라우저 내장 음성으로 읽어준다. **화면에 렌더된 문자열 그대로**를 읽으므로 새 내용이 생길 자리가 없다. 미지원 브라우저에서는 버튼을 그리지 않는다 | 사전 점검 결과 | 완료 |
| **해피콜 응답 연습** | 가입 후 오는 확인 전화에 **사실대로 답해도 된다는 것을 미리 연습**시킨다. 질문을 하나씩 내고, 답을 고르면 **그 답이 무엇으로 기록되는지 해설**이 열린다 — 해설을 건너뛰는 경로가 없다. 시나리오 2종(전화 가입 · 방카슈랑스, 분기 실사용) | 해피콜 `/happycall` | 완료 |

> **이 축은 생성형 AI를 호출하지 않는다.** 구조화 폼 + 도구 반환값 템플릿 렌더링, 그리고 배포 번들에 든 정적 시나리오만으로 동작하므로 **모델 장애 시에도 정상 동작**한다. 해피콜 연습의 진행·답변은 **클라이언트에만** 있고 서버로 가지 않는다 — 새로고침하면 처음부터이며, 연습이므로 그것이 맞다.

### 2.8 접근성 *(전 화면 공통 · 고령층이 주 사용자)*

본문 **18px 이상** · 터치 영역 **48×48px 이상** · 명도 대비 **4.5:1 이상** · **한 화면에 하나의 질문** · 화면 전환 시 제목으로 **포커스 이동**(스크린리더) · 처리 중 `aria-live` · 외부 폰트 미사용 · **카카오톡 인앱 브라우저 동작 확인** — **Lighthouse 접근성 — 측정한 8개 화면 전부 100점 · 실패 0**(랜딩·사전 점검·상담·검증 결과·해피콜·데모 3종), 기관·개발자 화면 6개도 전부 100점

> **100점은 바닥선이지 합격선이 아니다.** Lighthouse는 포커스 이동·탭 순서 같은 10개 항목을 「사람이 확인」으로 남기고 점수에 넣지 않는다. 실제로 100점 상태에서 결함이 나왔다 — 근거 각주 앵커의 터치 영역이 **21px**, 저장 안내 토글이 **31px**였다(둘 다 수정). 자동 점수 외에 본문 크기·터치 영역·전환 알림을 **직접 잰다.**

| **③ 판단** | 결론 + **확신도 1~5점** 생성 | **❌ 절대** | 읽기 | ❌ | **생성** |
| **④ 안내** | 판단을 **바꾸지 않고** 표현만 변환 (용어 풀이·다음 행동) | ❌ | 읽기 | ❌ | 읽기(수정 불가) |

**이 표는 프롬프트 지시가 아니라 타입으로 강제한다.** ③ 판단 계층의 입력 타입에는 원문 필드가 **존재하지 않는다** — 넘기고 싶어도 넘길 수 없다.

**런타임에 AI를 쓰지 않는 곳** — 예방 축 전체 · 본인 사건 ↔ 조정례 대조(구조화 값 비교라 지어낼 여지가 없다) · 유보 안내문 생성 · 분쟁 패턴 지표 · 해피콜 응답 연습 · 검증 결과 · 데모 3종

**뺀 것이지 안 쓴 것이 아니다.** 이 화면들이 보여주는 집계·점검 문장·시나리오는 틀리면 이용자가 잘못된 대비를 하는 자리라, 런타임 생성이 아니라 **사전 집계표와 코드 상수**에서 읽는다. 모델이 집계를 추정하면 그 자리가 그대로 환각 위험이 되고, 모델 장애 때 예방 축 전체가 함께 죽는다.

**대신 그 데이터를 모델이 만들었다.** 예방 축이 읽는 사전 집계표의 라벨(쟁점·상품군·판매채널·소비자 특성)은 **모델이 분류한 것**이며(`label_source='MODEL'`), 그 라벨을 교차집계한 표가 예방 축과 개선 축의 입력이다. 즉 **모델은 빌드 타임에 쓰고 런타임에는 굳힌 값을 읽는다.** 라벨 부착률은 축마다 달라 388건 중 판매채널 125 · 소비자 특성 39 · 배상비율 35이며, 화면은 **실제로 읽은 집계 축과 물러나 읽은 사실을 함께 표시**한다.

**이용 근거는 「인용」이다.** 금융감독원 저작권정책은 무단 복제·배포를 금하되
보도·비평·교육·연구를 위한 정당한 범위의 인용을 허용한다. 그래서 조정례 요지는
**발췌**해서 싣고(판단 결과 320자 · 근거 상세 700자) **원문은 금감원 공식 페이지
링크로 연결**하며, 출처를 전 화면에 표기한다. 전액 무상이라 영리 목적 이용도 아니다.
근거와 지키는 선 전체는 기획서 5.1에 있다.

### 4.3 개인정보·민감정보 처리

| 항목 | 처리 방식 |
|---|---|
| **대화·판단 저장** | **저장하지 않는다.** 진술·확정 슬롯·판단 결과·실행 로그를 **서버·DB·로그 어디에도 남기지 않는다** |
| **세션** | **AES-256-GCM으로 봉인해 이용자가 보유.** 서버에 상태가 없고 브라우저는 열어볼 수 없다. **유휴 30분 후 만료** |
| **개인식별정보** | 성명·계좌번호·주민등록번호·연락처를 **모델 전송 전 자동 마스킹**. 잔존 의심 시 **전송 차단 + 재입력 요청**(이중 방어) |
| **민감정보(건강정보)** | 진술 입력 **전에** 개인정보보호법 제23조에 따른 **별도 동의**. 미동의 시에도 병명·진료 내용을 빼고 이용 가능. **동의 기록도 보존하지 않는다** |
| **회원가입** | **없다.** 로그인 없이 이용 |
| **IP** | 남용 방지 목적으로만 **일시 처리**. 프로세스마다 다른 소금으로 해시해 앞부분만 카운트하며, **DB·로그에 저장하지 않고 최대 24시간 내 소멸** |
| **서버 로그** | 익명 세션 해시 · 이벤트 유형 · 도구명 · 소요 시간만. **본문이 남지 않는지 소스 스캐너로 상시 검사** |
| **외부 전송** | 마스킹된 진술 → Anthropic(미국) · 법령명·조문번호 → 법제처. 처리방침에 명시 |

**검증** — 합성 PII **132건 주입 테스트 미검출 0건**. 배포 조건으로 걸었고 CI에서 상시 검증한다.

> ⚠️ **「미검출 0건」은 그 세트 안에서만 참이다.** 레드팀 시험이 이 세트에 없던 변형 하나를 찾아냈다 — **주민등록번호 앞자리가 하이픈 없이** 오면(「앞자리가 800101인 주민번호예요」) 가리지도 막지도 않았다. 같은 날 고쳤고(맥락 낱말이 가까이 있을 때만 차단 — 「보험료 350000원」 같은 6자리 금액을 잘못 막지 않는 것까지 확인), **찾은 변형은 합성 세트에 편입했다**(117 → 132건). 넣지 않으면 다음 회귀에서 같은 구멍이 다시 열린다. 이 사실은 검증 결과 화면에도 공개한다.

**샘플 진술 ②** — 가입 시점이 빠져 있어 **되묻기(연·월 등)를 확인**할 수 있다

```
설계사를 통해 종신보험에 가입했습니다. 원금이 보장된다고 들었는데 해지하려니 낸 돈보다 훨씬 적게 돌려준다고 합니다. 가입할 때 예순여덟이었습니다.
```

**샘플 진술 ③** — **범위 외 요청 거절**을 확인할 수 있다

```
집주인이 전세보증금을 돌려주지 않습니다. 어떻게 해야 하나요?
```
→ 「이 내용은 다루지 못합니다」 + 다루는 범위 안내 + **금감원 1332 안내**

**예상 결과**

- **결론** 또는 **유보** 중 하나가 나온다. **둘 다 정상 동작이다** — 확신도 4점 미만이면 결론을 표시하지 않는 것이 설계다(검증셋 기준 **커버리지 27.1%**, 즉 100건 중 약 73건은 유보로 귀결된다)
- **같은 진술을 다시 넣으면 결과가 달라질 수 있다.** 이것도 설계가 아니라 실측된 성질이고, 그래서 검증 결과 화면이 **재현 2회를 회차별로** 공개한다 — 검증셋 120건 중 **두 번 모두 결론이 선 것은 25건**이었다
- **유보가 나오면 「자료를 보태서 다시 상담하기」를 눌러 보시기 바랍니다** — 동의·진술을 다시 받지 않고 이전 답변을 유지한 채 되묻기로 돌아가는 것을 확인할 수 있다
- 어느 쪽이든 **근거 3분류 · 자료 체크리스트 · 신청권 명시 · 1332 안내 · 실행 로그**가 함께 나온다
- ⚠️ **모델 출력이므로 문장 표현은 실행마다 조금씩 달라진다.** 고정된 것은 **화면 구성과 근거의 출처**이며, 근거로 표시되는 조문·판례·조정례는 **도구가 반환한 것만** 나온다

### 5.3 MVP 단계의 제한사항 — 심사 시 참고

**(1) 이용 한도 — 반복 시험 시 마주칠 수 있습니다**

비용 폭주 방어를 위해 상한을 걸어 두었습니다. **동일 IP 기준**입니다.

| 상한 | 값 | 초과 시 |
|---|---|---|
| **판단 실행** | **일 10회** | 「오늘 이용하실 수 있는 횟수를 다 쓰셨습니다」 |
| 상담 세션 생성 | 시간당 5회 | 대기 시간 안내 |
| 전체 요청 | 분당 30회 | 대기 시간 안내 |
| 일 예산 하드 쿼터 | 초과 시 **신규 상담만 차단** | **예방 축·검증 결과·데모 3종은 그대로 열립니다** |

> **판단을 여러 번 실행해 보실 계획이라면 상한을 염두에 두시기 바랍니다.** 상한에 걸려도 **경로 A(데모 3종)와 경로 B(예방 축), 검증 결과 화면은 영향을 받지 않습니다.**

**(2) 기능 범위**

- **파일 업로드가 없습니다** — 약관은 대화창 텍스트 붙여넣기(1회 4,000자)로 받습니다. 파일을 보관하지 않기 위한 선택입니다
- **로그인이 없어 이력이 남지 않습니다** — 결과는 화면에서 PDF·인쇄로 직접 남기실 수 있습니다
- 1차 적용 영역은 **보험 중심**입니다. 금융투자·은행 사건도 동작하나 코퍼스 비중이 낮습니다

**(3) 판단의 성격 — 화면에도 동일하게 고지합니다**

- **법률 자문이 아닙니다.** 실제 조정 결과를 예단하지 않습니다
- **민원 신청서나 법률문서를 작성하지 않습니다** (변호사법 제109조)
- **분쟁조정 신청 여부는 이용자 본인이 결정합니다.** 서비스는 신청을 말리지 않습니다
- **특정 금융회사를 평가하지 않습니다**

**(4) 성능·정확도의 한계 — 검증 결과 화면에서도 공개합니다**

- **커버리지 27.1% (65/240)** · CI [21.9, 33.0] — 100건 중 약 73건은 결론을 내지 않고 유보합니다. **낮은 수치를 그대로 공개**합니다. 회차별로 24.2%·30.0%였고, **재 볼 때마다 흔들리는 값이라 회차를 함께 적습니다**
- **유보 구간 정확도 64.6% (113/175)** — 「유보하지 않아도 됐을 사건을 유보했다」는 뜻이라 **이용자에게 불리한 수치이지만 그대로 공개**합니다
- **커버리지를 올릴 방법을 아직 찾지 못했습니다.** 세 번 시도해 세 번 기각했고, **기준은 결과를 보기 전에 고정했습니다.** 그중 둘은 **원래 유보하던 사건을 결론 내게 만든 구간에서만** 틀렸습니다 — 유보되는 사건이 실제로 더 어렵다는 뜻이지만, **커버리지가 낮다는 사실 자체는 해결되지 않았습니다.** 기각한 실험도 검증 결과 화면에 공개합니다
- **안전성 시험의 공격 문안은 저희가 직접 썼습니다.** 방어율은 「이 세트 범위에서 관측된 값」이며, 세트를 넓히면 구멍이 더 나올 수 있습니다 — 실제로 이번 시험이 하나를 찾았습니다
- **연령·소비자 특성별 정확도는 측정하지 못했습니다.** 특성 정보가 조정결정서의 「위원회 판단」 부분에만 있어, 입력으로 쓰면 정답 누출이 됩니다
- **정답은 「조정 결과」이지 법적 진실이 아닙니다.** 위원회 결정과 일치했다는 뜻이며 그 이상을 주장하지 않습니다
- 업권별 하위 그룹 수치는 **n이 작아 신뢰구간이 넓습니다.** 화면에서 **n·신뢰구간·단서를 항상 함께** 표시하며 퍼센트 단독 표시를 금지했습니다

**(5) 외부 의존**

- 법제처 API 장애 시 **캐시 스냅샷으로 폴백**하며, 「○월 ○일 확인 시점 기준」 배지로 폴백 사실을 표시합니다
- Claude API 장애 시 상담·판단 진입이 차단되나, **예방 축·검증 결과·데모 3종은 정상 제공**됩니다
