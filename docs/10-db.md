# DB 명세서
프리케이스(PreCase) — Supabase (PostgreSQL 15+)
<callout icon="🎯" color="blue_bg">
	**이 문서의 역할** — 데이터 요구사항(DR)의 엔티티를 **테이블·컬럼·제약·인덱스·뷰·권한** 수준으로 확정한다. 권한 요구사항 P-501·502의 자격증명 분리를 GRANT로 구체화한다.
	**여기 없는 테이블은 만들지 않는다.** 특히 세션 데이터(DR-4xx)의 테이블이 DB에 존재하면 그 자체가 설계 위반이다 (데이터 7장).
</callout>

## 2. 설계 원칙
<table header-row="true">
<tr>
<td>#</td>
<td>원칙</td>
</tr>
<tr>
<td>**D-1**</td>
<td>**열거는 CHECK, 미확정 열거는 룩업 테이블** — 확정 열거(channel·product·traits·verdict)는 CHECK 제약으로 고정한다. 유일한 미확정인 쟁점 태그(`issue`, U-9)는 **PostgreSQL enum 타입이 아니라 룩업 테이블**(`issue_tags`)로 둔다 — 값 확정이 스키마 변경 없이 데이터 적재로 끝나게 하기 위함</td>
</tr>
<tr>
<td>**D-2**</td>
<td>**UNKNOWN은 NULL로 저장** — 코퍼스에서 채널 미식별·특성 미명시는 NULL/행 부재로 표현한다. 런타임 슬롯의 `UNKNOWN`·`NONE`은 세션 개념이며 DB에 저장될 일이 없다</td>
</tr>
<tr>
<td>**D-3**</td>
<td>**브라우저 직접 접근 금지** — DB는 서버(Next.js 서버 액션·MCP 도구 서버)만 접근한다. 전 테이블 RLS 활성 + anon 정책 없음(deny-all)을 이중 방어로 둔다</td>
</tr>
<tr>
<td>**D-4**</td>
<td>**정적 자산은 버전으로 교체** — DR-1xx 테이블은 `corpus_version`/`batch_version`을 갖고, 배치가 스테이징 적재 → Q-1 누출 검사 통과 → 승격 순서로만 갱신한다 (9장)</td>
</tr>
<tr>
<td>**D-5**</td>
<td>**데모는 DB에 없다** — DR-107 데모 사례는 배포 번들 정적 자산이다 (예외처리 8장: DB 장애에도 데모 생존). 테이블을 만들지 않는다</td>
</tr>
</table>

## 6. DDL — 초기 마이그레이션(0001) 원문

⚠️ **정본은 리포의 `supabase/migrations/`다** (7장과 같은 판단). 아래는 **0001 시점의 원문**이며 이후 마이그레이션으로 달라진 부분이 있다 — `verdict`에서 PARTIAL 제거(0003) · `case_year` 하한 2000으로 완화 · `order_type`·`board`·`post_no`·`label_source` 추가. **코드와 대조하는 게이트는 문서가 아니라 DB를 읽는다**(`enums-db.test.ts`) — 문서가 마이그레이션보다 낡아 추출 게이트가 오작동한 사고의 재발 방지 장치다.
```sql
-- 전 테이블: RLS 활성 + anon 정책 없음(deny-all). 접근은 전용 롤로만 (8장)
create extension if not exists pg_trgm;

-- U-9: 값은 실물 라벨 적재로 확정 (10장 절차). enum 타입 아님 (D-1)
create table issue_tags (
  id          smallint generated always as identity primary key,
  code        text not null unique,
  label_ko    text not null,
  description text,
  active      boolean not null default true
);

create table cases (
  id                uuid primary key default gen_random_uuid(),
  source_type       text not null check (source_type in ('DECISION','SUMMARY')),
  decision_no       text,
  decision_date     date,
  sector            text not null check (sector in ('INSURANCE','INVESTMENT','BANKING','CARD','UNKNOWN')),
  product_code      text not null check (product_code in (
    'INS_SILSON','INS_WHOLE','INS_ANNUITY','INS_SAVINGS','INS_AUTO','INS_ETC',
    'INV_ELS','INV_FUND','INV_MARGIN','INV_ETC','BNK_LOAN','BNK_ETC','ETC_UNKNOWN')),
  channel           text check (channel in ('TM','BANCA_HS','AGENT','BRANCH','ONLINE')),
  verdict           text not null check (verdict in ('UPHELD','REJECTED','PARTIAL')),
  compensation_rate smallint check (compensation_rate between 0 and 100),
  facts_summary     text not null,
  panel_reasoning   text,
  source_url        text not null,
  case_year         smallint not null check (case_year between 2007 and 2100),
  is_validation     boolean not null default false,
  corpus_version    text not null,
  created_at        timestamptz not null default now(),
  constraint decision_fields check (
    source_type <> 'DECISION' or (decision_no is not null and decision_date is not null))
);

create table case_issues (
  case_id      uuid not null references cases(id) on delete cascade,
  issue_tag_id smallint not null references issue_tags(id),
  primary key (case_id, issue_tag_id)
);

create table case_traits (
  case_id uuid not null references cases(id) on delete cascade,
  trait   text not null check (trait in ('PRO','ELDER','INEXP','CAPACITY')),
  primary key (case_id, trait)
);

create table terms_clauses (
  id             bigint generated always as identity primary key,
  clause_text    text not null,
  sector         text check (sector in ('INSURANCE','INVESTMENT','BANKING','CARD','UNKNOWN')),
  product_code   text check (product_code in (
    'INS_SILSON','INS_WHOLE','INS_ANNUITY','INS_SAVINGS','INS_AUTO','INS_ETC',
    'INV_ELS','INV_FUND','INV_MARGIN','INV_ETC','BNK_LOAN','BNK_ETC','ETC_UNKNOWN')),
  source_case_id uuid references cases(id),
  corpus_version text not null
);

create table glossary_terms (
  id             bigint generated always as identity primary key,
  term           text not null,
  definition     text not null,
  source_case_id uuid references cases(id),
  corpus_version text not null,
  unique (term, definition)
);

-- 불변 자산: 배치 최초 적재 후 갱신 없음 (삭제 조문은 개정되지 않는다)
create table statute_snapshots (
  id           smallint generated always as identity primary key,
  law_name     text not null,
  article_no   text not null,
  article_text text not null,
  valid_from   date,
  valid_to     date,
  source_ref   text not null,   -- 국가법령정보센터 연혁법령 확보 경로 (DR-104 메타)
  captured_at  date not null,
  unique (law_name, article_no)
);

create table statute_timeline (
  id                smallint generated always as identity primary key,
  domain            text not null check (domain in ('SECURITIES','INSURANCE','COMMON')),  -- 증권·펀드 / 보험 / 공통
  law_name          text not null,
  article_no        text not null,
  applies_from      date,
  applies_to        date,
  successor_law     text,
  successor_article text,
  note              text
);

-- F-505 전용: 런타임 재계산·모델 추정 금지 (Q-4)
create table risk_patterns (
  id            bigint generated always as identity primary key,
  product_code  text check (product_code in (
    'INS_SILSON','INS_WHOLE','INS_ANNUITY','INS_SAVINGS','INS_AUTO','INS_ETC',
    'INV_ELS','INV_FUND','INV_MARGIN','INV_ETC','BNK_LOAN','BNK_ETC','ETC_UNKNOWN')),
  channel       text check (channel in ('TM','BANCA_HS','AGENT','BRANCH','ONLINE')),
  trait         text check (trait in ('PRO','ELDER','INEXP','CAPACITY')),
  issue_tag_id  smallint references issue_tags(id),
  n_cases       integer not null,
  n_upheld      integer not null default 0,
  n_rejected    integer not null default 0,
  n_partial     integer not null default 0,
  stat_basis    text not null default 'DECISION_235',
  batch_version text not null,
  computed_at   timestamptz not null,
  unique nulls not distinct (product_code, channel, trait, issue_tag_id, stat_basis)
);

-- S-06 단일 출처 (Q-3)
create table validation_stats (
  id            smallint generated always as identity primary key,
  category      text not null check (category in
                ('HEADLINE','SECTOR','METHOD','UNVERIFIED','CORRECTION_POLICY')),
  metric_key    text not null unique,
  display_ko    text not null,
  value_json    jsonb not null,   -- {value, numerator, denominator, ci_low, ci_high, note}
  display_order smallint not null,
  updated_at    timestamptz not null default now()
);

-- DR-201: 만료 행 보존 = 폴백 스냅샷
create table statute_cache (
  law_name       text not null,
  article_no     text not null,
  basis_date     date not null,
  article_text   text not null,
  effective_date date,
  source         text not null check (source in ('API','SNAPSHOT')),
  fetched_at     timestamptz not null,
  expires_at     timestamptz not null,
  primary key (law_name, article_no, basis_date)
);

-- DR-202: 정확 대조(F-502)는 캐시 적중과 무관하게 항상 수행
create table precedent_cache (
  case_no    text primary key,
  body       text not null,
  fetched_at timestamptz not null,
  expires_at timestamptz not null
);

-- DR-301: 식별 컬럼 금지
create table error_reports (
  id              uuid primary key default gen_random_uuid(),
  created_at      timestamptz not null default now(),
  masked_content  text not null,
  issue_code      text,   -- 쟁점 분류(선택) — 기획서 9.5 "쟁점·채널 단위 수집"
  channel         text check (channel in ('TM','BANCA_HS','AGENT','BRANCH','ONLINE')),
  status          text not null default 'RECEIVED'
                  check (status in ('RECEIVED','REVIEWING','CORRECTED','DISMISSED')),
  correction_note text,
  corrected_at    timestamptz
);

-- DR-302: 일 단위 집계 UPSERT만
create table usage_counters (
  event_type text not null check (event_type in
    ('JUDGMENT_DONE','WITHHELD','RECONSULT_ENTRY','REPORT_SUBMITTED','DEMO_VIEWED')),
  event_date date not null,
  cnt        integer not null default 0,
  primary key (event_type, event_date)
);

-- 뷰
create view citable_cases as
  select * from cases
  where source_type = 'DECISION' and decision_no is not null;

create view public_corrections as
  select id, created_at::date as reported_on, correction_note, corrected_at
  from error_reports
  where status = 'CORRECTED';

-- 인덱스
create index idx_cases_validation on cases (is_validation);
create index idx_cases_filter     on cases (sector, product_code, channel, verdict);
create index idx_cases_year       on cases (case_year);
create index idx_cases_facts_trgm on cases using gin (facts_summary gin_trgm_ops);
create index idx_case_issues_tag  on case_issues (issue_tag_id, case_id);
```

**구현 시 걸리는 제약 (B-4 실측, 2026.08.16)**

- **`error_reports`에 `insert ... returning`을 쓸 수 없다.** PostgreSQL은 RETURNING 절의 컬럼에 **SELECT 권한**을 요구하는데 `app_runtime`은 INSERT만 가진다. 권한을 넓히면 런타임이 남의 신고를 읽게 되므로 **접수번호(uuid)를 앱에서 생성해 명시적으로 INSERT**한다. 「접수분을 되읽을 수 없다」가 설계 의도이므로 이 제약은 유지한다 — `select ... from error_reports`가 거부되는 것을 테스트로 고정했다
- **`error_reports.channel`의 CHECK에는 `UNKNOWN`이 없다.** 슬롯 열거(`SLOT_CHANNELS`)는 UNKNOWN을 포함하므로 화면 값이 그대로 넘어오면 CHECK 위반으로 신고가 통째로 실패한다. 접수 계층에서 **UNKNOWN·미지 값은 null로 접고**, 접었다는 사실을 응답에 실어 알린다(신고 본문을 잃지 않는 쪽이 우선 — EP-3)
